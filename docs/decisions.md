# Architecture decisions

Two lines per entry: what was decided, and why. Newest at the bottom.

- **2026-10-18 — Fork lives at the repo root, upstream as a remote.** The GitHub fork is `zerokurns/meeting-control-center`; `origin` points at it and `upstream` at `ChurchApps/FreeShow`. Keeping upstream history intact (no squash, no reformat) keeps future `git merge upstream/main` cheap.
- **2026-10-18 — Develop on Node 24 LTS (nvm default), not upstream's Node 22.** Electron bundles its own Node at runtime, so the host version only affects tooling; 24 is this workstation's default and `engines` only requires `>=22.12`.
- **2026-10-18 — npm 12 security defaults are opted into per project, not bypassed.** `.npmrc` sets `allow-git=all` (upstream pins seven addons to GitHub commits, one of them transitive) and `allow-scripts-pin=false`; install scripts are approved by name in `package.json` `allowScripts` instead of `dangerously-allow-all-scripts`, so a new upstream dep with an install script still needs an explicit review.
- **2026-10-18 — GitHub git deps are fetched over HTTPS.** npm resolves `github:` shorthands to `git+ssh://` URLs; a user-level `url.https://github.com/.insteadOf ssh://git@github.com/` rewrite avoids needing a registered SSH key just to install.
- **2026-10-18 — The product spec lives in the repo at `docs/spec.md`.** Worker sessions get carryover from files, not chat, so the roadmap and kickoff prompt are versioned next to `decisions.md` and `dev-setup.md`.
- **2026-10-18 — Upstream's failing checks are recorded as a baseline, not fixed in the setup task.** 3 unit tests, 40 Prettier files and 195 svelte-check errors fail on untouched upstream code; fixing them now would create a large diff against upstream for no MCC value, so the rule is "don't make it worse" until the church-feature strip removes most of the affected files anyway.
- **2026-10-18 — Phase 1 PPTX support extends upstream's `src/electron/output/ppt/pptToPdf.ts` rather than adding a new sidecar.** Upstream already shells out to LibreOffice headless (with PowerPoint fallbacks) and feeds the PDF into the existing PDF.js item; MCC adds detection/download UX, background pre-render with progress, and notes extraction from the PPTX XML that `pptToShow.ts` already parses.
- **2026-10-18 — Church-feature strip ran as eight parallel Sonnet workers, one feature per commit, integrated by cherry-pick.** Each worker got a brief under `docs/tasks/`, a git worktree and a symlinked `node_modules`, and had to pass build, svelte-check (not above baseline), unit tests and the Playwright smoke test before committing; the orchestrator re-ran build + smoke after every cherry-pick. Conflicts were all "two strips removed different items from one line" and were resolved to the intersection.
- **2026-10-18 — The strip went beyond the kickoff's five features to the spec's full drop list.** Cloud sync, audio playlists/Spotify and the calendar were removed in the same task because `docs/spec.md` lists them under "Drop"; interactions (audience polls stored in upstream's own Firebase project) and telemetry (Google Analytics, Sentry, upstream update feed) are left for the rebrand task, where telemetry has to be repointed anyway.
- **2026-10-18 — Action API ids removed by the strip** (the existing Bitfocus Companion module may still reference them; everything else in `components/actions/api.ts` is unchanged): `start_metronome`, `clear_drawing`, `change_draw_zoom`, `transpose_show_up`, `transpose_show_down`, `start_scripture`, `scripture_next`, `scripture_previous`, `start_playlist`, `name_start_playlist`, `playlist_next`, `get_playlists`, `get_playlist`, `spotify_play`, `spotify_pause`, `spotify_fade_out`, `spotify_next`, `spotify_previous`. Remote-app socket messages `GET_SCRIPTURE`, `SEARCH_SCRIPTURE`, `SCRIPTURE`, `ACTIVE_SCRIPTURE` are gone too.
- **2026-10-18 — "Quick Lyrics" stays as "Quick text".** The paste-text-to-slides creator is useful for agendas; only the lyric web search, chord parsing and automatic verse/chorus detection were removed. Explicit `[Name]` section markers still work; unlabelled sections default to the "verse" group until groups are renamed for meetings.
- **2026-10-18 — Known leftovers after the strip, to pick up in later tasks:** the controller web app's draw pad (`src/server/controller/App.svelte`) is inert; `MEDIA_FOLDER_COPY` IPC and `getMediaSyncFolderPath` remain in main; `AiManager.processSTTChunk` is a no-op now that scripture detection is gone; saved audio routings may still contain `channel_metronome` / `playlist_*` nodes (inert); the `libspotifyctl` unpack glob in `config/building/electron-builder.yaml`; default song groups (verse, chorus…) in `src/electron/data/defaults.ts`.
- **2026-10-18 — MCC uses its own data locations; nothing is migrated automatically.** Package name `meeting-control-center` / product name `Meeting Control Center` give Electron a separate `userData` directory, and the default data root becomes `~/Documents/Meeting Control Center`. A FreeShow install on the same machine is left untouched; anyone who wants their FreeShow content copies the data folder and `userData` across by hand (see `docs/dev-setup.md`). Automatic migration would have to guess whether the user wants the fork to adopt FreeShow's data, and `config.dataPath` already lets a user point MCC at any folder.
- **2026-10-18 — Telemetry and upstream-hosted services are removed rather than repointed.** Sentry, Google Analytics, the update check against ChurchApps releases, the Firebase-backed interactions and internet remote control, and freeshow.net share links all go in task 4. Auto-update returns in Phase 4 against the fork's own releases; local error logging (`ERROR_LOG`) stays.
- **2026-10-18 — The Connect popup keeps its links to FreeShow's API and Companion documentation.** MCC's action API is intentionally wire-compatible with FreeShow's (same ids on 5505/5506, same OSC `/freeshow/*` prefix) so the existing Companion module works; until MCC has its own API page those docs are the accurate reference. Internal identifiers that are persisted or matched (`freeshow_project` import ids, `freeshow-protected://`, `freeshow-cache`, `FREESHOW_VAAPI_DEVICE`) also keep their names so existing files and setups keep working.
- **2026-10-18 — One document pipeline for all formats, PDF included.** Project items of type `document` (legacy `pdf` is treated the same) are previewed, navigated and output through the `DocumentViewer` contract in `src/frontend/viewers/types.ts`; the operator preview and the output layer mount whichever viewer the registry returns for the file. Upstream's separate `PdfPreview`/`PdfOutput` are folded into it so the agenda, keyboard, API and stage notes have one code path.
- **2026-10-18 — Files are copied into `<data>/Documents` on import; PowerPoint is converted there.** Keeps meetings self-contained and lets the converter run once, in the background, before the meeting. Notes come from the PPTX XML during import and travel with the item, so the stage display can show them after the deck has become a PDF.
- **2026-10-18 — XLSX renders as a styled read-only HTML table, no grid library.** SheetJS parses; `sheet_to_html` plus our CSS gives merges, widths and number formats, which is what a presenting view needs. Univer/Handsontable would add megabytes and a licence question for editing nobody does on stage. Revisit if charts or frozen panes become a request.
- **2026-10-18 — Known follow-ups after Phase 1 landed (not blockers for user testing):** the stage display does not yet show a document unit's speaker note (`stageTalk.ts` only sends show slide notes; needs a synthetic show or a new stage payload); a few legacy API paths (`play_media` with a PDF path, `getPDFThumbnails`) still emit `type: "pdf"` with `page/pages`, which the output reads fine; two agenda items pointing at the same file both highlight as active (matching is by path); dropped documents are appended at the end of the agenda regardless of drop position (import is asynchronous); the timer picker's "create new timer" opens the existing timer popup and the new timer must then be picked; documents are rendered on demand, not pre-rendered at import (the PDF cache keeps four documents and their thumbnails).
